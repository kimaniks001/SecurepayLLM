# H3 Mini — multi-party fairness and privacy explanation
19 November 2026 · Native Mini preview only

This builds on the approved H3 native Mini design; no separate
Living Workspace-style screen or new mini identity is created.

## Visible change
The compact, expandable What each party submitted section now displays
distinct original-party coverage: for example, 2 of 3 active traders
have submitted an account, and one still needs to be heard. Submitted
means a recorded statement, NOT proof, accepted terms or a KS001 finding.

It also explains that opening Mini Help is never itself authorization
to disclose another person's private review statements to an AI system.
A future joint automated examination must use separately recorded,
scope-limited, version-specific and withdrawable consent of the affected
parties. The UI does NOT provide a fake Grant consent button and
does not transmit content to a model.

Sample cases remain explicitly fictional. The real version-bound
first-party review list is preview-host gated and uses the same
authenticated Mini session. No browser-stored identities or model tokens.

## Source truth
Core H3 introduces exact party counts across the complete participant
response history, not the first 30 messages shown on the phone.
Two voices in a three-trader Agreement must not be called unanimous.

## Still blocked
No deployed Core H3 consent journal, authenticated grant/withdraw path,
certified model executor, living evidence examination, all-party
challenge workflow, or audited user acceptance is claimed.
The H3 Mini build checks the consent and 3-party demo copy
with native design-DNA source tests.

H3 is development-only; no production Money or signed Agreement change.
